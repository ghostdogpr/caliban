# Choose embedded runtime ownership and shutdown semantics

Type: `grilling`
Status: `resolved`
Blocked by: 03, 06, 09, 10, 11

## Question

How should the code-first embedded gateway acquire and own schemas, execution sources, transports, caches, and engine state within ZIO scopes; share the built runtime across concurrent requests; and drain, interrupt, and finalize it on application shutdown without leaks or detached work? Artifact serialization, standalone loading, hot reload, and cross-generation retirement are out of scope.

## Proposed answer

`Gateway.compose(...)` remains a pure reusable description. Its effectful `build` is scoped and returns one concurrently reusable gateway runtime whose lifetime cannot exceed the surrounding ZIO `Scope`. The exact public type and method signature belong to the public API ticket, but conceptually build requires `Scope` plus only build-time services and produces a runtime that retains its request-time environment type. It does not implicitly capture the application environment needed later by local Caliban graphs, effectful headers, tracing, or request services.

The runtime owns one immutable graph generation: composed schema and routing topology, planner state, built execution-source handles, source concurrency permits, admission state, bounded caches, and every gateway-created background fiber. It is built once and shared across requests. Coordinators, variables, entity batches, response stores, source documents, and result buffers are request-owned. Building the same composition description again creates an independent runtime with no hidden singleton state.

Resource ownership is explicit. The gateway finalizes clients, pools, caches, permits, scopes, and fibers that it constructs. Services supplied through the application environment are borrowed and never closed by the gateway. Their owner must keep them alive for the complete execution effect that receives them; an uninterruptible user-provided effect such as local Caliban execution, operation resolution, operation policy, or effectful header policy can extend that effect beyond its configured deadline. A generation may hold an owned or borrowed transport handle without exposing that distinction to the planner or scheduler.

Build independent sources concurrently under a small configurable construction bound. Acquire their runtime handles and schemas in the build scope, accumulate expected source/schema/composition diagnostics, and sort diagnostics deterministically rather than by completion order. Any expected failure produces no partial runtime and releases successful sibling acquisitions. Caller cancellation interrupts the whole build and fabricates no diagnostics. An unexpected defect remains a defect with its full `Cause`; scoped cleanup still runs.

All caches initially belong to the gateway runtime, including the schema-independent parsed-document cache. Parsed, negative, prepared, planned, and projection caches have separate finite estimated-weight budgets. Weight is a cheap monotonic structural estimate based on retained query bytes/characters, AST definitions and selections, prepared fields, plan nodes/edges, mapping instructions, and retained byte lengths—not reflective JVM object sizing. Release defaults only after the acceptance corpus measures allocation and live set; expose estimated weight, entries, hit/miss, admission, eviction, bypass, and single-flight metrics.

A valid operation larger than its cache budget executes without admission to that cache, subject to ordinary operation and plan limits. Transient failures are never cached. A small independent weight-and-TTL-bounded negative cache may retain only deterministic parsing, static validation, normalization, and planning failures under a key containing every schema/planning input that affects the result.

Cache misses use runtime-owned keyed single-flight. Each waiter may cancel independently; cancellation of the initiating request does not cancel work still needed by followers. The shared computation is interrupted when it has no waiters or the runtime closes. Insert only a successfully completed result. The atomic waiter/owner protocol prevents a new follower from racing an orphaned computation, and neither promises nor computation fibers detach from the runtime scope.

The runtime lifecycle is the one-way atomic state machine `Running → Draining → Closed`. Operation admission and active-registration occur in one atomic protocol: an operation cannot observe `Running`, race with drain, and become active afterward. A request whose deadline fires before its tree exits remains active and is also counted as overdue. Drain is explicit and interruptible. Entering `Draining` rejects new operations, removes queued admission waiters, and completes them with a typed draining outcome; only already-admitted operations continue. Concurrent drain callers await the same completion signal. Interrupting or timing out a drain waiter does not resume the runtime or cancel active work—the application may wait again or close the enclosing scope to force shutdown. The gateway itself owns no grace-period timer.

An operation remains active through source execution, response integration, null completion, final projection, and conversion into a caller-owned byte or Caliban result. Its interrupt-safe finalizer decrements active accounting exactly once only after no request-owned source buffer, response-store state, permit, or completion can escape. Caller cancellation remains ordinary ZIO interruption and cleans up through the same protocol.

Scope finalization is the forced-close safety net. It atomically enters `Closed`, wakes queued waiters, signals every active request scope and runtime-owned computation/background fiber with ordinary ZIO interruption, and fabricates no GraphQL response for application shutdown. Cooperative request work cleans up promptly; an uninterruptible user-provided effect remains inside its request scope and may delay finalization because neither its borrowed environment nor dependent resources may be released underneath it. Once structured users have exited, finalization closes generation-owned source clients and transports, invalidates caches/single-flight state, and releases schema/runtime state. Borrowed services are untouched. Closing and draining are idempotent, and every owned resource has exactly one finalizer.

Prefer atomic/idempotent ownership to interruption masking. Mask only short, guaranteed non-suspending state transitions and exactly-once handoffs. Admission waits, graceful-drain waits, child joins, transport shutdown, cache hooks, and user callbacks remain interruptible or independently time-bounded where gateway-owned. No unbounded wait occurs inside an uninterruptible scope finalizer, but an ordinary interruptible join may still await user code that has made itself uninterruptible; the gateway keeps the request active and observable, additionally counting it overdue only after its deadline fires, and neither detaches that code nor claims it was terminated.

Artifact serialization, standalone loading, graph replacement/hot reload, cross-generation cache reuse, retirement of old generations, process signal handling, and deployment packaging are explicitly deferred to a later Wayfinder effort based on the implemented and measured embedded runtime.
